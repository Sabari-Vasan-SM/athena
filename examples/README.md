# Examples

These files are not part of the npm package. They exist to show what Athena produces and how to wire it into a team workflow.

## demo-shop

[`demo-shop/`](demo-shop) is a small, realistic API: Express 5 routes for products and orders, a bearer-token middleware, a Prisma schema for PostgreSQL, a Vitest + Supertest test, a Dockerfile and a `.env.example` with variable names only (no real secrets, and no `.env`).

Everything in [`demo-shop/.athena/`](demo-shop/.athena) and [`demo-shop/AGENTS.md`](demo-shop/AGENTS.md) was generated by Athena and committed unedited. It shows, for example:

- `api.md`: the five routes with file and line evidence
- `database.md`: the `Product`, `Order` and `OrderItem` models, relations and the index
- `security.md`: `API_TOKEN` and `DATABASE_URL` recorded as secret-like variable **names**, and what Athena could not determine (CORS, rate limiting) marked `UNKNOWN`
- `deployment.md`: the Dockerfile, exposed port and environment variables
- `rules.md`: the starter rules file that is yours to edit

`state.json` and `model.json` are a local cache and are ignored by `.athena/.gitignore`, as in any project.

The example's application code is not installed or run by this repository's build or tests.

### Regenerate

From the repository root, with the CLI built:

```bash
npm run build:cli
cd examples/demo-shop
rm -rf .athena AGENTS.md
node ../../dist/cli.js init --agents agents-md
```

Commit the result without editing it. To check whether the committed knowledge still matches the code and the current analyzer:

```bash
node ../../dist/cli.js sync --check
```

The change hotspots in `debugging.md` come from this repository's Git history, so they can differ after regenerating. `sync --check` ignores them.

## github-workflow.yml

[`github-workflow.yml`](github-workflow.yml) is a complete workflow for the Athena GitHub Action (`uses: Sabari-Vasan-SM/athena@v0`): it checks that `.athena/` is in sync on every push and pull request, reviews pull request diffs for possible secrets and committed env files, and keeps one review comment up to date on the pull request. Copy it to `.github/workflows/athena.yml` in a project that has committed its `.athena/` folder. See [Use in CI and git hooks](../README.md#use-in-ci-and-git-hooks).
